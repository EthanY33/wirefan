A refused subscribe on load (the shared key is busy) is retried with jittered backoff. Other tabs in this browser are found with BroadcastChannel, which never touches the server.

Dev only (&dev=1). Raw WebSockets with no subscriptions: they raise the server's connection count until they close, and show as other connections, never as tabs on this channel.

What other tabs see

Object payloads get a _from field with this socket_id. The event frame itself carries no publisher identity (see the protocol), so _from is only a display hint.

Every visitor shares this channel, so the first screen never shows a payload's text. Other tabs list a custom payload as Custom message from ·XXXX; the text itself shows up only in their raw frames.

Want a quiet room? Add &channel=any-name to the URL and share that link.
